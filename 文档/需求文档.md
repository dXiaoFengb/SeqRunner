# 顺序任务调度器 V2 需求文档

来源：用户在 V2 规则适配计划中确认的继承需求，2026-11-02。

## 产品愿景
个人在 Windows 本地按预定顺序运行软件，减少重复操作并追踪结果。

## 一、项目目的
- 使用者：个人本地用户。
- 要解决的问题：多个软件的手动顺序运行与结果跟踪繁琐。
- 一句话目标：按配置顺序执行软件任务，支持计划、运行状态和历史查看。

## 二、功能任务
### 功能 1：本地软件顺序执行
- 优先级：主要。
- 使用场景：手动或通过计划依次启动已配置的软件。
- 验收标准：配置、保存和计划按用户选择生效；受控程序按顺序执行，完成、停止和失败可追踪；详细步骤见 `人工验收流程.md`。
### 功能 2：日志、设置与可选通知
- 优先级：次要。
- 使用场景：查看运行状态和历史，配置本地设置与可选通知。
- 验收标准：适用自动测试和隔离场景检查；真实外部通知须单独授权与验收。

## 三、明确不做与技术约束
- 明确不做：当前不建设云端多用户或远程集中管理。
- 技术约束与关键选择：沿用 Python 3.13、FastAPI、Vue、TypeScript 和 Electron；继承已有本地实现与 Windows 交付。
- 非功能要求：用户数据与凭证受保护；真实业务、外部通知与系统操作按当前授权执行。
- 数据、权限与外部依赖：以 `CONSTRAINTS.md` 为准；可选 QQ 和 Webhook 的真实访问须另行授权。
- 异常处理与回退要求：保留失败证据，不覆盖既有用户数据、验证包或历史提交。

## 四、怎么交
- 交付形态：Windows EXE，免安装完整文件夹。
- 用户审核启动入口：根目录 `验证审查器.cmd`。
- 打包命令：明确授权后按 README 的 V2 准备与最终核验命令执行；本轮未实际打包。
- 最小启动 / 健康检查方式：隔离数据启动源码，检查窗口、API、实时连接及受管进程关闭。
- 同目录依赖文件：按实际构建生成的 Electron 运行依赖与后端资源；具体清单待真实构建核验。

## 五、怎么验收
日常按影响范围定向验证；阶段性完整核查按功能清单、全量自动回归、隔离预览及 `人工验收流程.md` 分类记录；真实业务、真实外部通知、DPI、EXE 和异机验证按实际授权和执行结果记录。

# 顺序任务调度器

> 一个独立的 Windows 本地任务调度器：按顺序启动用户配置的程序，以人工确认、进程退出或日志信号确认结果，完成收尾与冷却后再继续下一项。

## 设计原则

- 默认轻量：目标、范围和验收明确的普通任务可直接执行。
- 按需升级：只有新项目立项或需求未收敛时，才进行完整需求澄清。
- 高风险严格：删除、整体覆盖已有文件或产物、迁移、权限调整、发布、外部写入、推送和改写 Git 历史须单独确认。
- 单一事实来源：同一类事实只在一个文件维护，其余位置只引用。

## 核心文件与事实来源

| 文件 | 负责的唯一事实 |
| --- | --- |
| `AGENTS.md` | 通用流程、未配置时的安全默认、值语义与写入权限 |
| `CONSTRAINTS.md` | 长期红线、长期预先授权、Git、记录与高风险历史策略 |
| `TASK.md` | 当前任务定义、边界、待决事项与唯一任务状态 |
| `handoff.md` | 本次交接周期的快照：最近改动、证据和下一步 |
| `VERSION.md` | 发布动作定义、版本和发布历史 |
| `README.md` | 项目概况、构建/测试入口和本文档导航 |

核心文件始终保留：没有适用内容时填「无」或「不适用」，而不是删除文件并制造悬空引用。逐轮对话记录不是核心文件，但本模板默认由 `CONSTRAINTS.md` 要求创建；只有用户明确例外时才不创建。

## 初始化

项目复制后，`CONSTRAINTS.md` 中的「项目状态」默认为“模板”。只有以下字段已经由用户确认、或填入其允许的已决定值后，执行者才可将其改为“已初始化”，并写入确认来源：

1. `CONSTRAINTS.md`：适用于本项目的配置字段不存在“待填写 / 待确认 / 未知”、取值有效，并满足该文件规定的条件依赖；默认启用的 Git 提交策略与对话记录策略无需重复确认，只有用户明确选择例外时才调整；`.gitignore` 核验与相关依赖仍须满足。自动提交在每轮产生持久改动或需留痕项目事实时按 `AGENTS.md` 的固定路线执行，不逐次询问。表中的“—”和无需初始化的正文不作为配置字段。
2. 发布与提交相关字段：按 `VERSION.md` 规定的当前发布模式及其依赖字段全部完成；Git 提交策略为“自动提交”或“手动提交”时，「开发提交版本」也须已定义；
3. 本文件：技术栈、目录结构、构建命令、测试命令；不适用的字段须明确填“不适用”。

项目名称不是初始化前置条件。仍未确定的产品或任务问题集中记录在 `TASK.md` 的「待决问题」。这不是全仓库扫描规则；源代码、Issue 或普通文档中的 `TODO` 不影响项目初始化状态。

## 使用路径

### 只读答复

审查、解释、问答或信息确认不写任何项目文件。只读取回答所需的目标文件；若宿主已注入 `AGENTS.md`，无需重复读取。

### 快速修改

用于明确、单点、可逆的修改。先读取 `AGENTS.md` 和 `CONSTRAINTS.md`；产生持久改动时，在 `TASK.md` 记录最少任务事实。高风险操作不因任务小而免除确认。

### 普通开发

在 `TASK.md` 建立任务卡，明确目标、修改边界、完成标准和验证方式后执行。续接顺序见 `AGENTS.md`。

### 新项目立项

产品愿景、项目目的、功能任务、明确不做与技术约束、交付、验收或三个任务边界尚未完整确认时，使用 `TASK.md` 的「新项目立项」章节逐节澄清；不得仅因已回答两三个初步问题就结束立项。每次提问的候选方向、答复不清时的追问、关键选择及其理由、实现前反向审查、提问结束的硬性条件与正式需求文档输出均以 `TASK.md` 的该章节为准；未满足其“提问结束”条件前，不得将候选、建议或假设定为最终方案，也不得开始实现执行。用户已一次提供完整信息时，只补问未覆盖的章节。立项的边界与授权不另设重复章节，以 `TASK.md` 最小任务卡的三个边界字段和 `CONSTRAINTS.md` 为准。

## 项目档案

- 项目名称 / 定位：顺序任务调度器；独立精简版本地 Windows 桌面程序。用户界面的每条“软件脚本”恰好对应一个软件；内部继续兼容后端 `queues/tasks` 数据键。定时仅由“计划管理”的多软件计划承担：计划草稿可先保存为空任务或单任务，只有手动、启动时和定时实际运行前才要求至少两个不同的软件任务；到点时按任务列表顺序执行当天匹配“运行周几”的项目。“运行全部脚本”仍只支持手动开始。旧多程序脚本会安全拆分，旧单软件定时槽会在创建本地恢复副本后清空，用户需在计划管理重新建立多软件计划。
- 技术栈：Python 3.13、FastAPI、Pydantic、psutil、Uvicorn `websockets` 协议实现、PyInstaller、Vue 3、TypeScript、Vite、Electron、electron-builder。
- 目录结构（源 / 测试 / 产物 / 发布）：`backend/` 为本地服务、预设证据元数据与测试；`frontend/` 为 Vue 脚本管理、独立编辑页及连接控制模块；`electron/` 为安全主进程/preload；`scripts/` 为读取 `VERSION.md` 的本地打包入口；`data/` 为本地配置和日志（不纳入 Git）；`frontend-dist/`、`portable/`、`build/`、`release/` 及 `portable-validation-v*` 为本地构建或验证输出（不纳入 Git）；不进行发布。Electron 默认原生菜单已移除，应用内“设置”是唯一设置入口。脚本首页为一行式软件卡，只提供检索、创建、全量运行和软件级操作；独立编辑页一次只配置当前软件，采用路径导航、单张配置卡、说明提示、连续分区、基本信息双列和运行配置栅格。字段自动保存保留，同时提供“保存更改”作为立即确认入口；首页状态按该软件的实时运行项显示，而非整轮状态。
- 预设路径：选择预设时即显示本地证据表中的只读模板成功/失败规则；输入或选择匹配 EXE 后完整应用名称、参数、工作目录、日志、超时、完成方式与自动终态规则。用户规则在“添加自定义规则”中单独保存，重复模板规则会被拒绝。MAA 专用页只提供安卓模拟器 ADB 预检（失败仅警告，仍启动 MAA GUI），不改写 MAA 或模拟器配置；MaaEnd 专用页只提供本轮受管 Windows 游戏→等待→MaaEnd 启动编排，按开关仅收尾本轮创建的游戏 PID。MAA、绝区零一条龙具有日志终态规则，MaaEnd、三月七小助手和 BetterGI 保持人工确认回退。应用不会在运行时访问外网或改写目标软件配置。
- 失败可追溯：整轮终态仅刷新运行历史而不覆盖本地脚本草稿。运行中心以整合状态徽标显示来源、计划名称、当前软件、进度、失败项、计划跳过和完成后操作倒计时；只在实际运行、人工确认、收尾冷却或完成后操作等待时，滚过观察点后收拢为可展开的紧凑吸顶条。完成、失败和停止终态保持在当前页面的正常文档流，“查看失败详情”会定位并展开相应历史记录，显示完成来源、退出码和日志摘要。计划因执行器忙碌而跳过时，不进入后台队列，并将计划名、预定时间和原因保存在当前轮与历史中。计划可设置启动时运行（否、是、每日首次启动时）、定时运行开关，以及只在整轮成功时生效的完成后操作；延时结束后总会先显示 60 秒可取消倒计时，新运行会自动取消待执行操作。
- 构建命令：`npm run build`；`npm run package:backend` 生成隐藏控制台的后端；`npm run package:win` 生成 Windows portable EXE；`npm run package:validation` 读取 `VERSION.md` 的开发提交版本，将验证包、后端资源和下载缓存写入对应的 `portable-validation-vXYZ/` Git 忽略目录（均不代表发布）。每轮开发改进或本地提交的直接相关验证完成后，必须生成新的独立验证包、记录 SHA-256 并执行隐藏健康检查；既有验证包不得覆盖。
- 测试命令：`backend\.venv\Scripts\python.exe -m pytest backend/tests`、`backend\.venv\Scripts\python.exe -m ruff check backend`、`corepack npm run typecheck`、`corepack npm run test:frontend`、`corepack npm run build`、`corepack npm run electron:health`。
- 发布路径与动作：见 `VERSION.md`
- Git 与记录策略：见 `CONSTRAINTS.md`

> 当前任务和状态看 `TASK.md`；交接进展看 `handoff.md`；发布事实看 `VERSION.md`。本文件不复制这些事实。

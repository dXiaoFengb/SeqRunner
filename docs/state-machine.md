# 运行状态机

## 队列与任务状态

每次“开始脚本”都深拷贝脚本和任务配置，运行中的轮次不会受界面保存影响。全局只有一个 `RunnerEngine`；第二个手动开始返回忙碌错误，定时触发记录“因忙跳过”。“运行全部脚本”会按持久化脚本卡顺序，将所有程序展开为同一条手动运行记录；它不增加全局定时，也不改写现有单脚本计划。

任务状态按以下路径迁移：

```text
queued → validating → starting → monitoring / waiting_manual
  → succeeded / failed → closing → force_closing（仅正常关闭超时）
  → cooling_down（仅仍有下一项）→ succeeded / failed → 下一任务或 completed

任一非终态 → stopped（全局停止）
```

- `validating`：检查可执行文件，并在启动前取得日志游标。
- `monitoring` / `waiting_manual`：并发监听人工确认、进程退出、成功/失败日志、超时和停止。第一个终态信号锁定结果。人工确认仅在当前运行项允许确认且仍处于 `waiting_manual` 时被接受；重复、过期或不匹配确认会返回明确错误。
- `succeeded`：人工确认、成功日志或符合条件的零退出任一先到。随后请求目标主窗口关闭，等待 3 秒，再只强制结束本轮保存 PID 的进程树；仅在仍有下一项时冷却 10 秒。运行快照会提供 `cooldownUntil`（服务端 UTC 截止时刻）与兼容字段 `cooldownSeconds`，界面据此显示秒级倒计时；最后一项收尾后直接结束整轮。
- `failed`：启动失败、失败日志、非零退出、已配置成功日志却提前退出、超时或日志读取错误。也执行同一受管收尾；仅中间项冷却 10 秒后继续，最后一项直接记录整轮完成且在运行中心提示存在失败项。
- `stopped`：全局停止取消监听和冷却，只收尾当前受管 PID，绝不派发下一项。

整轮状态为 `running → completed`，或在停止后为 `running → stopping → stopped`。每轮记录每项状态、完成来源、退出码、时间、错误摘要和有限日志摘要到 `data/history.json`；全部脚本运行另记录 `run_mode=all_scripts`，每项保留所属脚本 ID/名称。旧历史缺少这些字段时按单脚本、无归属读取。

## 不变式

1. 任意时刻最多一个活动队列，且不为重复手动或定时触发排队。
2. 一个任务的第一个成功或失败终态信号即锁定结果；后续信号不改变该记录。
3. 启动前日志游标只允许消费本轮的新内容；截断或轮转后重新衔接。存在成功日志规则（可为多条）时，零退出不能当作成功兜底；预设的人工确认回退不会把普通退出误标成功。
4. 进程处理仅使用本轮启动后保存的 PID、创建时刻和子树；不会按名称、窗口标题或全局扫描结束用户进程。
5. 冷却和停止期间不会启动下一项；应用退出走同一停止路径。
6. “运行全部脚本”若任一脚本为空、程序路径为空、预设路径不匹配或预设规则未应用，则整轮不会启动，也不会静默跳过该脚本。
7. 终态实时快照只触发该轮运行历史的单飞刷新，不回读或覆盖本地配置草稿；存在失败项时运行中心保留失败程序、所属脚本和错误摘要，并可定位到展开的历史记录。

## 连接与便携启动不变式

- Electron 为每次后端启动生成实例标识。后端只绑定随机回环端口并在 `/health` 回传同一标识；主进程验证匹配后才显示窗口，渲染进程不会硬编码端口。
- renderer 没有 Node 权限；只经受限 preload 获取连接地址与 `.exe` 文件选择结果。主进程隐藏后端窗口，受管目标进程在 Windows 使用 `CREATE_NO_WINDOW`。
- 便携版的本地数据位于 EXE 同级 `data/`；开发版位于项目根目录 `data/`。两者均不纳入 Git。
- 连接状态分为 REST 在线、实时在线、实时重连中和后端不可用。只有 REST 健康检查或 REST 请求失败才禁用保存、运行和停止；实时通道短暂断开时以低频 REST 轮询维持运行视图。
- 同一时刻最多保留一个 WebSocket、一个重连计时器和一个初始化请求。旧会话的关闭事件由代际标识忽略，不能重启新的重连链。
- 客户端每 20 秒发送一次 `ping`，服务端在同一会话回复 `pong`；45 秒未收到实时消息才关闭并重连。重连采用有上限的指数退避和轻微随机抖动，诊断记录关闭码、原因、次数、下次时间与最近成功时间。
- 后端在输出 `RUNNER_READY` 前验证 `websockets` 协议实现可导入，并显式让 Uvicorn 使用该实现；缺失依赖会以启动诊断失败，不会伪装成前端 `1006` 重连。PyInstaller 也收集该实现及其子模块。
- 本地表单保存采用带修订号的单通道：每次只提交最新配置快照，过期响应不得回写界面。选择 EXE 会先更新本地草稿与工作目录；预设文件名不匹配时保留路径并阻止运行，直到重新选择或显式切换为通用程序。
- 输入 EXE 与原生文件选择共用同一预设同步路径：名称精确匹配时才应用本地预设证据、参数、日志和完成规则；响应返回前若路径或预设已改变则丢弃该响应。失配时清除旧预设证据，确保刷新后仍保持不可运行状态。
- Electron 退出只对它启动并持有 PID 的后端根进程树执行 Windows `/T` 收尾；不按名称枚举或结束用户进程。这样可覆盖 PyInstaller 无窗口启动器的子进程。

## 定时策略

定时槽为“星期 + HH:mm”，绑定整条队列。每分钟检查当前和过去十分钟的时点，已触发键持久化在配置中以避免同分钟和重启重复运行。闲置时，十分钟窗口内只补跑一次；超过窗口记录跳过。忙碌时直接记录“因忙跳过”，不补跑。

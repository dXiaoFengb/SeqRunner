# Windows 人工验收步骤

自动化测试不代替此验收。日常使用请双击便携 EXE；`启动器.bat` 只用于开发环境检查。若开发检查提示缺少环境，按提示安装本项目依赖后重新启动。

每轮开发改进或本地提交的直接相关验证完成后，均会生成独立、Git 忽略的 portable 验证包，完成 SHA-256 与隐藏健康检查；这不代表发布，也不会覆盖既有包。本轮 v0.5.0 验证包的实际路径、大小与 SHA-256 见 `handoff.md` 和对话记录。

1. 双击 `portable-validation-v050\\electron\\顺序任务调度器-v0.5.0-portable.exe` 打开应用。预期只出现应用主窗口，不出现命令提示符黑框、`File / Edit / View / Window / Help` 英文原生菜单，也绝不显示 `ERR_FAILED (-2) loading ...\\Temp\\...\\index.html`；原生标题栏和左侧品牌区均显示“顺序任务调度器 v0.5.0”，设置页保留“开发版本 v0.5.0”。在“设置”确认“应用信息”和“连接诊断”分区、API 在线、实时状态已连接，且 EXE 同级 `data\\logs\\` 已出现应用日志。若启动失败，展开诊断并记录其中文提示与日志末尾内容，停止后续步骤。
2. 保持应用空闲至少 3 分钟。预期实时状态不反复跳为“重试中”；如确有断开，诊断应显示关闭码/原因/下一次时间，且 API 仍在线时“新建脚本”、保存、运行和停止不会被禁用。
3. 在“脚本”页新建两个软件脚本。每次新建应直接生成一张“新程序”软件卡，而非空脚本或“添加程序”入口。可使用 Python 解释器作为程序路径，并以 `-c` 加短脚本作为参数；不要配置真实业务程序。确认首页每条卡只显示拖拽把手、软件名、路径摘要、预设、状态、“编辑脚本”“运行”“更多”，不显示程序数、队列、程序预览、展开控件或可编辑字段。点击“编辑脚本”必须进入该软件唯一的一份完整配置表单：顶部仅有“脚本管理 / 编辑软件”路径导航、返回和运行时的全局停止；其下是一张主配置卡，卡头包含“软件名称 脚本配置”、预设标签、保存状态与“保存更改”，并含使用说明。“基本信息”必须以较窄的软件名称左列和较宽的程序完整路径/选择软件右列组成；“运行配置”中预设独占一行，参数、工作目录、日志文件、超时为两列栅格；控件始终为深色，不出现浏览器默认白色输入框。其后按“预设自动规则”“完成信号”“危险操作”连续分区，不出现程序顺序、选择其他软件或添加程序。缩小至约 960px 后双列应改为单列，无重叠或横向溢出。修改字段后确认顶部先显示保存中、再显示已保存；点击“保存更改”后确认明确显示保存完成。断开后端后修改，确认显示未保存草稿 / 等待后端恢复，恢复连接后不会丢失当前草稿。返回后仍回到软件卡列表。复制软件脚本后检查其定时槽未被复制。拖动软件卡或在“更多”中使用“上移/下移”后关闭再打开，确认排序已保存。
4. 建立两个临时软件脚本，让第一项启用“人工确认”。手动开始“运行全部脚本”后点击“确认完成”。预期按钮立即变为“确认已接收”，顶部“运行中心”依次显示“正在请求程序正常关闭”“正在收尾受管进程”以及“第 N 项已完成，X 秒后启动下一程序”；十秒倒计时每秒可见变化，第二个软件只在倒计时结束后启动。第一张软件卡在第二项开始时应显示“已完成”和完成来源，第二张卡才显示“运行中”或当前等待/收尾状态，第一张不得仍显示“运行中”。第二项成功或失败收尾后，不再显示十秒倒计时，直接显示“整轮执行完成”（失败时提示存在失败项），两张卡均显示各自最终结果而非“运行中”。
5. 两个软件脚本都完整配置后，点击“运行全部脚本”，确认严格按软件卡顺序串行执行，并在历史中显示所属软件脚本。故意清空任一路径后再点击，预期整轮被阻止且列出问题，不得只运行其余软件；脚本管理页不得出现任何定时控件。若升级前存在多程序脚本或旧单软件定时，先备份 `data/config.json`，启动后确认应用额外生成 `data\\backups\\config-before-v3-*.json` 本地恢复副本、旧脚本拆分为多个软件卡、全部旧单软件定时已清空并出现“请在计划管理重新创建多软件计划”的中文提示。
6. 分别用零退出、成功日志和失败日志验证完成来源、失败后继续和日志摘要。日志测试应使用临时日志文件，确认启动前已有的成功文本不被误判。存在失败项时，确认运行中心显示最终 `N/N`、失败程序所属脚本和错误摘要；点击“查看失败详情”后应跳转到历史页并展开本轮失败项，显示完成来源、退出码与日志摘要。
7. 在“计划”页先确认无计划时仅显示大面积居中的“暂无计划 / 还没有创建任何计划”，没有边框提醒卡；软件不足两个时“新建计划”禁用并有原因说明。创建计划后，确认页面依次为“计划选择”与单张当前队列配置卡，卡片顶部依次显示“队列类型、启动时运行、定时运行、完成后操作”，下一行显示“延时执行（分钟）”；“循环队列（下一版本提供）”可见但不可选。确认启动时运行提供“否、是、每日首次启动时”，且第二个非“否”计划会被保存校验拒绝；定时运行设为“否”后时间表保留但不参与触发或同刻冲突。

8. 在计划的“定时列表”添加两条定时，确认每行包含拖拽顺序、启用、可展开的周一至周日多选、小时与分钟选择、删除；拖拽后关闭再打开确认顺序保存。首次添加定时后，确认“任务列表”出现；添加至少两个不同软件任务，逐项打开“运行周几”多选，确认上移、下移、拖拽和删除都保存。为即将到来的分钟设置时间，并只给其中一个任务选择当天，确认只运行匹配任务；如果当天没有匹配任务，历史显示“当天没有匹配‘运行周几’的软件任务”，且不启动程序。尝试保存两个启用计划相同星期、相同时间的槽，确认界面与保存接口直接指出冲突。计划运行期间命中另一计划，确认运行中心和历史显示计划名、预定时间及“因上一计划尚未完成而跳过”，且没有排队重跑。

9. 仅使用受控临时软件脚本，给计划设置任一完成后操作和 0 分钟延时。整轮成功后，确认运行中心显示 60 秒倒计时、将执行的操作和“取消完成后操作”；取消后历史记录取消原因。开始一轮新的手动运行，确认旧倒计时自动取消。让任一任务失败、停止或当天无匹配任务，确认不显示完成后操作倒计时。不要在人工验收中选择关机、强制关机、重启、休眠、睡眠或注销；若需验证实际系统动作，必须获得单独确认。
10. 运行时点击“全局停止”，确认当前受管 PID 被收尾、冷却取消且不启动下一项；随后关闭主窗口，确认应用退出且没有遗留本轮后端。
11. 在独立编辑页分别选择五个预设并输入或点击“选择软件”选择对应 EXE。选择模板后，立即确认“模板成功规则 / 模板失败规则”以只读列表显示；匹配 EXE 后 MAA 与绝区零一条龙应填入软件名（仅原为“新程序”时）、工作目录、日志路径、参数、600 秒超时与完成方式。展开“添加自定义规则”后，确认自定义成功/失败规则独立于模板规则；输入与模板相同的规则应被拒绝。MaaEnd、三月七小助手和 BetterGI 应填入路径/工作目录、已证据参数与人工确认回退。选择匹配的 `MaaEnd.exe` 后确认不出现对象克隆错误，安装目录、工作目录、超时和预设规则正常回填。故意输入不匹配 EXE，确认路径仍显示、预设证据被清除、运行被禁用，并只能通过“重新选择”或明确点击“切换为通用程序并保存”后继续；不得静默套用预设规则。
12. 打开脚本卡“更多”菜单，确认其覆盖于卡片上方、不被裁剪、不挤动相邻脚本；“删除脚本”与其他菜单项左侧、行高和内边距一致。点击空白处或按 Esc 后关闭并将焦点返回“更多”。滚动独立编辑页，确认左侧导航始终固定，顶部运行中心在运行时始终可见；缩小窗口至约 960px，确认导航收缩、编辑表单改为单列且页面不横向溢出；打开“设置”确认版本、连接、诊断及数据边界可见。

13. 仅使用受控临时路径验证专用页，不启动真实业务软件。选择 MAA 模板后，确认基本信息显示“MAA 安装目录”，专用区只显示“安卓模拟器连接”、ADB 程序、连接地址与检测结果，不显示实体安卓设备、账号、代理或游戏更新字段；故意填写无效 ADB 后点击检测，预期显示警告，并确认说明仍会由 MAA GUI 继续尝试连接。选择 MaaEnd 模板后，确认只显示安装目录与“Windows 游戏启动编排”：游戏 EXE、参数、等待秒数和“结束后关闭本轮启动游戏”开关；不显示 ADB、分辨率、控制器或 MaaEnd 内部任务配置。使用受控夹具时确认游戏→等待→MaaEnd 的顺序，并确认停止只收尾本轮受管 PID。

记录每一步的观察结果、Windows 版本和任何异常；真实程序路径、参数、日志位置与完成规则仍需用户另行提供。

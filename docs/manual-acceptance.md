# Windows 人工验收步骤

自动化测试不代替此验收。日常使用请双击便携 EXE；`启动器.bat` 只用于开发环境检查。若开发检查提示缺少环境，按提示安装本项目依赖后重新启动。

本轮已生成 Git 忽略的单文件验收包 `portable-validation-v021\\electron\\顺序任务调度器-v0.2.1-portable.exe`，大小 95,382,239 字节，SHA-256 为 `BEC73EFB07A1EAED5DD8C9EDAB0FC28BEA97D04A185C87BD87523A4B9FBFD1CB`。该包的隐藏健康启动退出码为 0；它不覆盖既有 EXE，并显示开发提交版本 `v0.2.1`。自动化健康检查不能替代本步骤。

1. 在 single-file portable EXE 生成并提供 SHA-256 后，双击新 EXE。预期只出现应用主窗口，不出现命令提示符黑框，且绝不显示 `ERR_FAILED (-2) loading ...\\Temp\\...\\index.html`；原生标题栏和左侧品牌区均显示 `v0.2.1`。在“设置”确认 API 为在线、实时状态已连接，且同级 `data\\logs\\` 已出现应用日志。若启动失败，展开诊断并记录其中文提示与日志末尾内容，停止后续步骤。
2. 保持应用空闲至少 3 分钟。预期实时状态不反复跳为“重试中”；如确有断开，诊断应显示关闭码/原因/下一次时间，且 API 仍在线时“新建脚本”、保存、运行和停止不会被禁用。
3. 在“脚本”页新建两个脚本，每个脚本添加一个临时测试程序。可使用 Python 解释器作为程序路径，并以 `-c` 加短脚本作为参数；不要配置真实业务程序。确认搜索、全部展开/收起、“编辑脚本”“运行”“更多”可用；点击“编辑脚本”必须进入独立完整编辑页，返回后仍回到脚本卡列表。复制脚本后检查其定时槽未被复制。拖动脚本卡或使用“上移/下移”后关闭再打开，确认排序已保存。
4. 让第一项启用“人工确认”。手动开始脚本，确认第一项已启动后点击“确认完成”。预期按钮立即变为“确认已接收”，顶部“运行中心”依次显示“正在请求程序正常关闭”“正在收尾受管进程”以及“第 N 项已完成，X 秒后启动下一程序”；十秒倒计时每秒可见变化，第二项只在倒计时结束后启动。
5. 两个脚本都完整配置后，点击“运行全部脚本”，确认严格按脚本卡顺序串行执行，并在历史中显示各程序所属脚本。故意清空任一脚本的程序或路径后再点击，预期整轮被阻止且列出问题，不得只运行其余脚本；“计划”页仍只能为单条脚本配置时间。
6. 分别用零退出、成功日志和失败日志验证完成来源、失败后继续和日志摘要。日志测试应使用临时日志文件，确认启动前已有的成功文本不被误判。
7. 在“计划”页为脚本添加接下来一分钟的定时槽，确认它从第一项启动；在脚本运行期间命中另一槽，确认界面/日志提示“因忙跳过”，且没有排队重跑。
8. 运行时点击“全局停止”，确认当前受管 PID 被收尾、冷却取消且不启动下一项；随后关闭主窗口，确认应用退出且没有遗留本轮后端。
9. 在独立编辑页分别选择五个预设并输入或点击“选择软件”选择对应 EXE。MAA 与绝区零一条龙匹配后应立即填入工作目录、日志路径、参数及“预设自动规则”中的成功/失败规则；MaaEnd、三月七小助手和 BetterGI 应填入路径/工作目录并显示“需人工确认”。故意输入不匹配 EXE，确认路径仍显示、预设证据被清除、运行被禁用，并只能通过“重新选择”或明确点击“切换为通用程序并保存”后继续；不得静默套用预设规则。
10. 打开脚本卡“更多”菜单，确认其覆盖于卡片上方、不被裁剪、不挤动相邻脚本；点击空白处或按 Esc 后关闭并将焦点返回“更多”。滚动独立编辑页，确认左侧导航始终固定，顶部运行中心在运行时始终可见；缩小窗口至约 960px，确认导航收缩、任务表单改为单列且页面不横向溢出；打开“设置”确认版本、连接、诊断及数据边界可见。

# Windows 人工验收步骤

自动化测试不代替此验收。验收范围、证据方法和状态记录以 `REVIEW.md` 为准；日常使用请双击便携 EXE，`启动器.bat` 只用于开发环境检查。若开发检查提示缺少环境，按提示安装本项目依赖后重新启动。

每轮开发改进或本地提交的直接相关验证完成后，均会按 `GIT.md`、`CONSTRAINTS.md` 生成独立、Git 忽略的 portable 验证包，完成 SHA-256 与隐藏健康检查；这不代表发布，也不会覆盖既有包。本轮应使用 `TASK.md`「本轮验收目标 EXE」指定且已核验 SHA-256 的独立验证包，并与 `VERSION.md` 开发提交台账、当前 `handoff.md` 和对应对话记录交叉核对。该字段为“不适用”或健康检查未通过时，不得把任何历史包当作本轮通过的人工验收目标。

1. 双击 `TASK.md`「本轮验收目标 EXE」指定且已核验的 `产物/验证/vX.Y.Z/` 根目录 portable EXE 打开应用。预期只出现应用主窗口，不出现命令提示符黑框、`File / Edit / View / Window / Help` 英文原生菜单，也绝不显示 `ERR_FAILED (-2) loading ...\\Temp\\...\\index.html`；原生标题栏、左侧品牌区和设置页显示的开发版本均应与该验证包对应的开发版本一致。在“设置”确认“应用信息”和“连接诊断”分区、API 在线、实时状态已连接，且 EXE 同级 `UserData\\logs\\` 已出现应用日志。仅用临时夹具验证迁移：在不存在 `UserData\\` 的副本旁同时放置 v0.12 旧 `用户数据\\config.json`、`history.json`、`backups\\` 与 `detail_logs\\`，以及更旧的 `data\\`；首次启动后确认这些兼容条目复制到 `UserData\\`、旧目录均未删除，且 v0.12 的 `用户数据\\` 优先于 `data\\`。再预建不同内容的 `UserData\\config.json`，确认它优先且不会被任何旧目录覆盖。若启动失败，展开诊断并记录其中文提示与日志末尾内容，停止后续步骤。
2. 保持应用空闲至少 3 分钟。预期实时状态不反复跳为“重试中”；如确有断开，诊断应显示关闭码/原因/下一次时间，且 API 仍在线时“新建脚本”、保存、运行和停止不会被禁用。
3. 在“脚本”页新建两个软件脚本。每次新建应直接进入“新程序”的完整编辑草稿，而不是先自动持久化空脚本或显示“添加程序”入口；未点击保存后返回并选择放弃时，首页不得留下该新脚本。可使用 Python 解释器作为程序路径，并以 `-c` 加短脚本作为参数；不要配置真实业务程序。确认首页每条卡只显示拖拽把手、软件名、路径摘要、预设、状态、“编辑脚本”“运行”“更多”，不显示程序数、队列、程序预览、展开控件或可编辑字段。点击“编辑脚本”必须进入该软件唯一的一份完整配置表单：顶部仅有“脚本管理 / 编辑软件”路径导航、返回和运行时的全局停止；其下是一张主配置卡，卡头包含“软件名称 脚本配置”、预设标签、保存状态与“保存更改”，并含配置顺序说明。表单依次显示“1. 软件预设”（独占首个分区）、“2. 脚本与程序”（软件名称与程序完整路径/安装目录）、“3. 常用运行设置”、“4. 日志来源”、“5. 完成信号”，之后才显示预设专用设置、预设自动规则与危险操作。控件始终为深色，不出现浏览器默认白色输入框。缩小至约 960px 后双列应改为单列，无重叠或横向溢出。修改字段、选择预设或程序路径后，确认不发出配置保存且顶部显示“有未保存更改”；点击“保存更改”后确认显示保存中、绿色“已保存”和“保存成功”。点击返回或侧栏切换时，确认出现“保存并离开 / 放弃更改 / 继续编辑”；保存失败或后端离线时草稿不丢失。返回后仍回到软件卡列表。复制软件脚本后检查其定时槽未被复制。仅从卡片左侧拖拽把手调整软件脚本顺序，关闭再打开后确认排序已保存；“更多”菜单不得显示“上移”或“下移”。
4. 建立两个临时软件脚本，让第一项启用“人工确认”。手动开始“运行全部脚本”后点击“确认完成”。预期按钮立即变为“确认已接收”，顶部“运行中心”依次显示“正在请求程序正常关闭”“正在收尾受管进程”以及“第 N 项已完成，X 秒后启动下一程序”；十秒倒计时每秒可见变化，第二个软件只在倒计时结束后启动。第一张软件卡在第二项开始时应显示“已完成”和完成来源，第二张卡才显示“运行中”或当前等待/收尾状态，第一张不得仍显示“运行中”。第二项成功或失败收尾后，不再显示十秒倒计时，直接显示“整轮执行完成”（失败时提示存在失败项），两张卡均显示各自最终结果而非“运行中”。
5. 两个软件脚本都完整配置后，点击“运行全部脚本”，确认严格按软件卡顺序串行执行，并在历史中显示所属软件脚本。故意清空任一路径后再点击，预期整轮被阻止且列出问题，不得只运行其余软件；脚本管理页不得出现任何定时控件。若升级前存在多程序脚本或旧单软件定时，先备份 `data/config.json`，启动后确认应用额外生成 `data\\backups\\config-before-v3-*.json` 本地恢复副本、旧脚本拆分为多个软件卡、全部旧单软件定时已清空并出现“请在计划管理重新创建多软件计划”的中文提示。
6. 分别用零退出、成功日志和失败日志验证完成来源、失败后继续和日志摘要。日志测试应使用临时日志文件，确认启动前已有的成功文本不被误判。存在失败项时，确认运行中心显示最终 `N/N`、失败程序所属脚本和错误摘要；点击“查看失败详情”后应跳转到历史页并展开本轮失败项，显示完成来源、退出码与日志摘要。

   使用受控程序分两次写入成功或失败标记并在两次写入之间留出读取时间，确认跨片段的关键词和正则可识别，中文字符拆分写入也能识别；同次读取同时包含成功和失败时失败优先。截断或轮转后不应把旧文件末尾与新文件开头拼成信号。跨片段正则依赖超过 64 KiB 的历史上下文时不保证命中。
7. 在“计划”页先确认无计划时仅显示大面积居中的“暂无计划 / 还没有创建任何计划”和页头“新建计划”，不显示编辑表单、计划卡列表或“连接与设置”。即使尚未创建软件脚本，页头新建入口仍可创建空草稿并直接进入独立“编辑计划”页；使用“返回计划列表”回到概览。创建第二个计划后，确认概览按纵向逐行显示独立计划卡：每行左侧仅有拖拽柄和序号，中部为名称及定时摘要，右侧为只作用于该行的“编辑计划 / 删除计划”；不得出现“新建计划”虚线卡、全局选中态或全局编辑/删除栏。点击第二行的编辑或删除时，必须只编辑或删除第二个计划。仅从卡片左侧手柄拖拽，或聚焦手柄后按 Alt + 上下方向键，可调整卡片显示顺序；重开页面确认显示顺序保存，但每个计划内设置的星期与时间不被改写。缩小到约 980px 时，操作区应移至同一计划卡底部；约 620px 时操作按钮纵向排列，均不得横向溢出。进入编辑页后，确认标题旁铅笔原位重命名、返回按钮、深色字段和定时/任务表可用，编辑页不重复显示删除计划。五个字段“队列类型、启动时运行、定时运行、完成后操作、延时执行（分钟）”均有问号按钮：悬停、聚焦和点击时显示中文深色说明，Esc 或点击外部关闭，窄窗口不遮挡表单；“循环队列（下一版本提供）”可见但不可选。确认启动时运行提供“否、是、每日首次启动时”，且第二个非“否”计划会被保存校验拒绝；定时运行设为“否”后时间表保留但不参与触发或同刻冲突。

   8. 在计划的“定时列表”添加两条定时，确认每行包含左侧唯一拖拽顺序、启用、默认全选的“周一 ×”至“周日 ×”标签、小时与分钟选择、删除；点击标签的 × 可移除单日，点击控件空白处或箭头会展开定位在该字段的深色两列星期面板。宽屏时面板必须悬浮在触发字段上方，不改变表格行高、任务列表位置或页面滚动尺寸；面板中已选项必须有青蓝色勾选与背景差异，未选项保持中性深色；取消最后一个运行日时应保持原选择并显示“请至少选择一个运行日”，不能显示 JSON 或技术字段。缩小窗口后浮层改为随字段向下纵向展开，不应遮挡删除或添加操作、也不应横向溢出。首次添加定时后，“任务列表”应出现且初始为空，保留表头并显示图标、“尚未选择软件脚本”及中文引导。点击“＋ 添加任务”后应先出现一条“未选择脚本”行；只在该行下拉选择已编辑并保存的软件脚本后才写入任务。任务“运行周几”同样采用标签和深色勾选面板；任务行没有上移/下移按钮，只有左侧拖拽柄排序与删除；拖拽时名称、运行周几与删除操作应和序号整行一起移动。单软件任务可保存并由手动、启动时或定时计划执行；空计划命中时历史显示“计划尚未添加软件脚本，已跳过本次执行”，不启动程序且不影响后续调度。为即将到来的两个不同分钟设置两个计划、再将计划卡顺序反转，确认先处理较早的预定时间而非较前的卡片；尝试保存两个启用计划相同星期、相同时间的槽，确认界面与保存接口直接指出冲突。计划运行期间命中另一计划，确认运行中心和历史显示计划名、预定时间及“因上一计划尚未完成而跳过”，且没有排队重跑。

9. 仅使用受控临时软件脚本，给计划设置任一完成后操作和 0 分钟延时。整轮成功后，确认运行中心显示 60 秒倒计时、将执行的操作和“取消完成后操作”；取消后历史记录取消原因。开始一轮新的手动运行，确认旧倒计时自动取消。让任一任务失败、停止或当天无匹配任务，确认不显示完成后操作倒计时。不要在人工验收中选择关机、强制关机、重启、休眠、睡眠或注销；若需验证实际系统动作，必须获得单独确认。
10. 运行时点击“全局停止”，确认当前受管 PID 被收尾、冷却取消且不启动下一项；随后关闭主窗口，确认应用退出且没有遗留本轮后端。
11. 在独立编辑页分别选择五个预设并输入或点击“选择软件”选择对应 EXE。选择模板后，立即确认“模板成功规则 / 模板失败规则”以只读列表显示；匹配 EXE 后 MAA 与绝区零一条龙应填入软件名（仅原为“新程序”时）、工作目录、日志路径、参数、600 秒超时与完成方式。展开“添加自定义规则”后，确认自定义成功/失败规则独立于模板规则；输入与模板相同的规则应被拒绝。MaaEnd、三月七小助手和 BetterGI 应填入路径/工作目录、已证据参数与人工确认回退。选择匹配的 `MaaEnd.exe` 后确认不出现对象克隆错误，安装目录、工作目录、超时和预设规则正常回填。故意输入不匹配 EXE，确认路径仍显示、预设证据被清除、运行被禁用，并只能通过“重新选择”或明确点击“切换为通用程序并保存”后继续；不得静默套用预设规则。
   12. 打开脚本卡“更多”菜单，确认其覆盖于卡片上方、不被裁剪、不挤动相邻脚本；菜单只提供“复制脚本”和“删除脚本”，不得显示“上移”或“下移”，且“删除脚本”与其他菜单项左侧、行高和内边距一致。点击空白处或按 Esc 后关闭并将焦点返回“更多”。实际运行、人工确认、收尾冷却或完成后操作等待时，滚动使完整运行中心越过页面标题，确认它才收拢为同宽紧凑吸顶条，显示状态、来源、当前软件、进度以及确认或取消关键操作；“展开运行详情”可由键盘操作并正确展开/收起。完成、失败或停止且无待执行操作时，切换到脚本、计划、历史或设置并滚动，确认完整终态只在页面正常流中显示、不会吸顶遮挡表单。缩小窗口至约 960px，确认紧凑条、导航和编辑表单都改为单列且页面不横向溢出；打开“设置”确认版本、连接、诊断及数据边界可见。

13. 仅使用受控临时路径验证专用页，不启动真实业务软件。选择 MAA 模板后，确认基本信息显示“MAA 安装目录”，专用区只显示“安卓模拟器连接”、ADB 程序、连接地址与检测结果，不显示实体安卓设备、账号、代理或游戏更新字段；故意填写无效 ADB 后点击检测，预期显示警告，并确认说明仍会由 MAA GUI 继续尝试连接。选择 MaaEnd 模板后，确认只显示安装目录与“Windows 游戏启动编排”：游戏 EXE、参数、等待秒数和“结束后关闭本轮启动游戏”开关；不显示 ADB、分辨率、控制器或 MaaEnd 内部任务配置。使用受控夹具时确认游戏→等待→MaaEnd 的顺序，并确认停止只收尾本轮受管 PID。
14. 使用受控窗口检查 MAA 编辑页“界面日志区域”：选择与配置路径匹配的窗口、框选、预览并保存，重新打开编辑页确认区域保留；取消或识别失败不覆盖旧设置。改变窗口客户区尺寸或遮挡所选区域，应暂停并提示原因；窗口布局变化时重新框选。受控运行期间验证新增内容显示在侧栏和对应任务历史，首次基线、中断以及 OCR 可能错字或遗漏的提示清晰；原始日志仍可切换。实际 MAA 的普通/卡片布局、最小化、多 DPI 和 OCR 效果单独人工验收，不得将夹具结果当作实机验收。

15. 使用受控窗口在通用软件和各预设的编辑页检查“界面日志区域”：查看窗口画面、框选标记、放大区域及识别文字，保存后重新打开并选择匹配窗口；检查选框与真实位置一致，预览不得混入桌面或其他窗口；遮挡、最小化或改变尺寸应暂停并说明原因。核对直接界面文本来源与画面识别备用的简洁提示。使用受控临时日志文件夹，确认只读取直接子文件中匹配 `*.log;*.txt` 的多份日志；左侧脚本日志顶部按文件名、`界面读取` 或 `画面识别` 显示来源标签，最新来源默认选中，手动选择另一来源后不得被其他来源新内容强制切走；未选中来源在最后查看后产生新增内容时显示活动标记，切换查看该来源后仅清除该来源标记，新运行或快照重同步不得带入上一轮标记。断开并恢复实时连接或人为制造来源序号断档后，当前来源正文应从快照恢复，不重复、不串入上一轮；出现“实时缓冲已截断”时到历史页直读原文件。用短暂占用后解除的受控文件验证读取会恢复；连续不可读才明确失败。将旧文件改名轮转并立即创建同名新文件，确认旧文件未读尾部先被读取而不回读历史内容。仅对已发现的外部文件、关闭人工确认并显式填写“日志无新增保护（秒）”时，确认新增字节会重置计时、超过阈值失败；留空、未发现文件、窗口/画面识别或人工确认任务均不得触发该规则。历史页入口名为“查看脚本内部日志”，弹窗顶部右侧可选择蓝色当前文件和其他文件，底部“加载更多、复制当前已读取内容、导出原文件、打开所在文件夹”按钮靠右。删除源文件后应显示不可读取，不得回退到本软件副本。没有文件日志和框选区域的脚本运行时，左下角只保留本轮软件日志；有日志时“本轮日志摘要”默认始终跟随最新内容，以校验、运行、等待确认、收尾、冷却、完成或失败的彩色阶段标识显示。尚未点击“确认当前程序完成”时，应已从运行快照看到校验、启动和等待确认摘要；在同一运行中断开并恢复实时连接后，它们仍应被恢复，重复或断档事件不得造成重复或缺项。手动向上查看旧日志后，下一条本轮或脚本日志到达时两个日志面板都必须自动回到最新；不得显示“回到最新”“回到底部”或未读数量。运行受控成功和失败脚本，确认历史显示实际结果，“查看本轮运行日志”包含本工具检查、启动、收尾和总耗时；清理旧脚本详细日志后整轮日志仍在。旧记录应提示无法还原完整日志。

16. 使用受控窗口核对窗口预览和选区画面顶部、底部齐平，细长选区完整且不变形，窄窗口可换行。使用受控的同路径已有实例验证 MAA 启动前提示自行关闭，已有进程不被关闭；普通提前退出仍显示实际失败。用中文和彩色文字夹具验证 OCR 追加及遮挡恢复，检查首次基线不进入历史，不能确认连续性时提示可能遗漏。实际 MAA 界面与不同 DPI 的效果另行人工验收。

17. 在脚本编辑页切换各预设与通用程序，确认三月七以文字和颜色标识界面文本读取及框选备用，其他预设与通用程序标识可框选画面识别，窄窗口不遮挡控件。仅使用受控程序验证：勾选人工确认后，成功日志及零退出均不启动下一项，即使同时勾选正常退出也须等待确认；随后分别检查确认、失败日志、非零退出、停止和超时。取消人工确认及正常退出时，零退出不得判成功；独立检查成功日志和启用正常退出的原有完成方式。

18. 仅使用受控、脱敏日志夹具验收可读报告：在运行中确认左侧“本轮日志摘要”上方只显示引擎已经确认的中文进度（例如“正在等待人工确认”），不得把 OCR、窗口文本或未知脚本原文误译成完成结论。完成后进入“日志”，确认宽屏左侧日期/运行记录导航有成功、失败、停止的状态区分；右侧一级“运行报告”只显示结论、耗时、完成依据、风险和可点击的脚本选项卡，悬停不得自动切换。点击整张脚本卡或以 Tab 后按 Enter/空格必须进入独立的“脚本运行详情”页面：该页面只保留全局导航、详情面包屑、最终状态、完成依据、耗时、来源状态和只读的代码式“本软件事件流”，不得残留一级日志页标题、筛选栏、日期/运行导航或任务列表；返回运行报告后保留筛选、当前运行、任务列表滚动位置及触发项焦点。此事件流必须标明“根据已确认运行事实生成，不是脚本原文，不参与终态仲裁”。为“含 ERR 但最终成功”的夹具确认风险提示为“检测到错误级脚本日志，但未构成终态失败”，但最终结论仍以引擎终态为准；未知等级文本只显示数量，不作业务解释。旧历史记录必须保留原有信息并说明该历史项未保存可读报告。

   二级详情右上角仅在历史项已有授权外部文件时显示“查看脚本内部日志”；没有可读文件时应显示真实来源状态，而不得伪造可用入口。“查看界面采集日志”只用于界面采集/旧本地详细日志；两类日志不得混同。分别打开两类入口：确认只读阅读器具有行号、查找、自动换行、可见滚动条、字号与隐藏空行控制；时间戳、等级、模块、路径、URL 和 JSON 显示不同颜色。确认“当前仅搜索已读取内容”只适用于已加载分页，加载更多后正文追加；复制、导出原文件和打开所在文件夹仍只对当前任务配置或历史中已授权的文件生效。断开恢复、文件不可读和大日志分页均只用受控夹具验证，不读取或复制真实业务日志。

19. 使用受控历史记录验证关键词、触发来源与日期范围以交集筛选：关键词只查已保存的运行/任务名称、错误摘要、本轮摘要、计划跳过与本软件可读报告，不读取原始日志正文；“重置”应恢复最近一周、空关键词和“全部触发来源”。脚本任务选择区在宽屏和窄屏均从上至下紧凑排列，不出现横向滚动；超过约五项时仅该列表内部纵向滚动，不挤压左侧运行导航。每项整行均可点击或经 Tab 后按 Enter/空格进入详情，悬停只高亮而不自动切换。人工验收仅使用受控夹具，不读取用户业务数据或外部原始日志。

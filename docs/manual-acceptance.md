# Windows 人工验收步骤

自动化测试不代替此验收。日常使用请双击便携 EXE；`启动器.bat` 只用于开发环境检查。若开发检查提示缺少环境，按提示安装本项目依赖后重新启动。

本轮待验收文件为 `portable-validation-v012-r3\\electron\\顺序任务调度器-0.1.0-portable.exe`，SHA-256：`0BF038DA8DA2CD5C038E5C610B4ACBD1D265E59AE3F0853EF0B3B02D6AC97582`。它是本地验证证据，不是发布物；不会覆盖 `release/` 或既有 EXE。此包从 asar 内的应用路径加载前端入口，并包含显式 WebSocket 协议实现、单通道保存和受控后端进程树收尾。请在普通 Windows 桌面会话中进行以下验收；自动化健康检查不能替代本步骤。

1. 双击该 EXE。预期只出现应用主窗口，不出现命令提示符黑框，且绝不显示 `ERR_FAILED (-2) loading ...\\Temp\\...\\index.html`；在“设置”确认 API 为在线、实时状态已连接，且同级 `data\\logs\\` 已出现应用日志。若启动失败，展开诊断并记录其中文提示与日志末尾内容，停止后续步骤。
2. 保持应用空闲至少 3 分钟。预期实时状态不反复跳为“重试中”；如确有断开，诊断应显示关闭码/原因/下一次时间，且 API 仍在线时“新建脚本”、保存、运行和停止不会被禁用。
3. 在“脚本”页新建一个脚本，添加两个临时测试程序。可使用 Python 解释器作为程序路径，并以 `-c` 加短脚本作为参数；不要配置真实业务程序。确认搜索、全部展开/收起、“编辑脚本”“运行”“更多”可用；复制脚本后检查其定时槽未被复制。
4. 让第一项启用“人工确认”。手动开始脚本，确认第一项已启动后点击“确认完成”。观察其受管进程被关闭，界面显示十秒冷却，第二项随后才启动。
5. 分别用零退出、成功日志和失败日志验证完成来源、失败后继续和日志摘要。日志测试应使用临时日志文件，确认启动前已有的成功文本不被误判。
6. 在“计划”页为脚本添加接下来一分钟的定时槽，确认它从第一项启动；在脚本运行期间命中另一槽，确认界面/日志提示“因忙跳过”，且没有排队重跑。
7. 运行时点击“全局停止”，确认当前受管 PID 被收尾、冷却取消且不启动下一项；随后关闭主窗口，确认应用退出且没有遗留本轮后端。
8. 在“脚本”页分别选择五个预设并点击“选择软件”。MAA 与绝区零一条龙应只接受对应 EXE；MaaEnd、三月七小助手和 BetterGI 应显示“需人工确认”。故意选择不匹配 EXE，确认路径仍显示、运行被禁用，并只能通过“重新选择”或明确点击“切换为通用程序并保存”后继续；不得静默套用预设规则。
9. 缩小窗口至约 960px，确认导航收缩、任务表单改为单列且页面不横向溢出；打开“设置”确认连接、诊断及数据边界可见。

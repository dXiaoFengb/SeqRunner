# 审核覆盖矩阵

`tools/feature-preview/audit-coverage.json` 是本项目审核领域、定向测试、受控场景、高风险 EXE 门禁与人工验收编号的唯一机器可校验来源。本文件只说明使用方式，不重复维护领域清单。

## 日常功能审核

1. 在 `TASK.md` 填写功能批次标识、涉及模块、预览检查项、必跑自动检查和 EXE 门禁结论；跨任务累计只写入 `docs/审核批次状态.md`。
2. 按 JSON 中所选领域运行定向测试；任何矩阵引用缺失时先运行 `npm run validate:audit-coverage` 并修复引用，不得猜测覆盖范围。
3. 有用户可观察变化时，用 `tools/feature-preview/New-FeaturePreview.ps1` 创建 `产物/预览/<功能批次>/运行/<YYYYMMDD-HHmm-序号>/`；只把批次根的 `打开最新预览.cmd` 和 `当前预览.md` 交给用户，不让用户从历史运行目录中选择启动器。
4. 记录“定向自动化”和“功能预览”各自的实际结论；二者不等于 EXE 验证或人工验收。

## EXE 门禁

矩阵标为 `highRisk: true` 的领域必须在累计状态中标为“待批次验证”，但不即时打包。每累计 5 项只提示一次；只有用户明确说“打包验证”时，才按 `GIT.md` 与 `VERSION.md` 运行完整回归、验证包、SHA-256、隐藏健康检查、隔离 CDP 验收和适用的 `docs/manual-acceptance.md` 步骤。

## 维护规则

新增或删除受控场景、定向测试或审核领域时，先更新 JSON，再运行 `npm run validate:audit-coverage`。审核提示词、模板和人工验收说明只能链接该矩阵，不能复制已执行场景或过时文件名。

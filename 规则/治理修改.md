# 治理规则修改

- 何时读取：准备改变规则含义、权限、默认值、必填结构，或治理写入未被责任模块明确覆盖时。
- 职责：治理语义变更及未覆盖写入的授权核对；不接管责任模块已明确允许的日常事实更新。
- 必要前置：用户当前要求、已确认需求与授权来源、受影响规则及 `CONSTRAINTS.md` 适用边界。
- 输出位置：本次明确授权的治理文件和相应决定记录，不自行扩大任务范围。

本模块内路径以项目根目录为基准；引用只作导航，仅在对应动作触发时读取。

任一治理文件中构成规则的内容，包括触发条件、允许值、必填字段、判定标准、流程要求、默认值和权限强度，实质变化须用户明确确认。`AGENTS.md` 与 `CONSTRAINTS.md` 的字段取值及适用范围只能依据用户明确确认、已确认需求或其他可追溯来源更新；更严格专项规定仍适用。

新增治理文件、新增必填字段或提高规则强度须用户确认；优先合并、删除或复用既有字段。任务本身明确要求修改治理文档时，按用户已确认范围执行，不就相同授权重复确认。

日常事实更新权限分别由责任模块持有：任务和交接由 `规则/任务执行.md`、开发版本由 `规则/版本管理.md`、打包准备及验证台账由 `规则/打包验证.md`、发布事实由 `规则/正式发布.md`、忽略核验结论由 `规则/Git提交.md`、初始化状态由 `规则/初始化.md` 管理。只更新对应事实时按该模块，不额外读取本模块；这些许可不授权改规则或扩大当前边界。

`README.md` 已确认项目事实、实际命令及失效引用，以及任一治理文件无语义变化的拼写、格式和失效引用，执行者可在任务范围内自行修正，不得借此改变触发、范围、默认值或权限。`CONSTRAINTS.md` 长期取值实质变化须同步日期与来源；`.gitignore` 由已核验退回待确认属于收紧，不更新该组日期与来源。

未被适用规则明确允许的写入，不得仅以“当前任务事实”为由推定可自行更新；只有明确记录要求、用户当场指令、已确认需求等授权来源成立时才可执行。临时例外只记录当次对象及确认来源，不改长期红线；改变长期策略须明确确认，且仍受写入边界限制。

# 源码预览

- 何时读取：创建、修改、检查或运行源码预览入口；日常功能改进需要尝试预览时。
- 职责：固定双击入口、依赖与数据隔离、关闭方式、预览证据及失败反馈，不负责 Git、EXE 打包或发布。
- 必要前置：核对当前任务范围、`CONSTRAINTS.md` 的只读资产与操作边界，以及实际启动命令；涉及实际构建或测试入口时读取 `README.md` 的对应项目事实。
- 输出位置：根目录预览入口及适用的使用说明；本轮结果按 `对话记录/记录规则.md` 留痕。只读审查只报告，不写文件。

本文件中的路径以项目根目录为基准。引用只用于定位；只有当前动作触发对应职责时才读取其他模块。本规则不创造额外操作授权。

## 固定双击入口

在项目根目录提供名称固定为 `验证审查器` 的双击入口，扩展名和实现形式按技术栈选择；双击后直接打开当前源码对应的软件内容，不因此打包 EXE。优先兼容 Windows 自带工具。说明实际入口路径、依赖、首次启动方法、使用的数据、隔离方式和关闭方法，避免测试误用真实数据。

使用 CMD 时，固定开头依次为：

```bat
@echo off
setlocal
cd /d "%~dp0"
```

入口只执行到达审核对象所需的本地步骤。静态检查入口与直接调用脚本；不得夹带发布、上传、下载、外部写入、清理、迁移、删除、Git 推送或改写历史等未获授权动作。调用链无法判断时，不得把静态检查写成通过。前置条件不足时显示原因及建议并返回非零结果；CMD 失败窗口应保持可见。

## 执行与结果

在本轮授权和安全边界内尝试适用的源码预览；无法保障隔离或需要额外授权时停止相关步骤，说明原因并完成其他可安全检查。首个源码入口尚未实现时，如实说明并完成适用的直接检查，不因缺少 EXE 而阻止留痕。

分别记录“启动器静态检查”“启动器运行”“程序或页面可见”“人工验收完成”的实际状态，按“通过 / 失败 / 未执行 / 不适用”报告；前一项通过不代表后一项通过。源码预览、自动测试、EXE 验证与人工验收分别记录，不把启动成功说成全部功能通过。

预览失败或环境无法运行时，保留实际改动和本轮开发版本，记录失败原因、未验证项与重试方式，并明确告诉用户：**本次预览失败，需要重新执行。** 不得将失败或未执行写成通过。预览失败本身不阻止本地 Git 检查点；其他必要检查、授权或提交安全前置仍须满足。仅执行预览不加载 Git、打包或发布流程。

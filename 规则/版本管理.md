# 开发版本管理

- 何时读取：完成一轮功能改进、准备更新开发版本时；纯非功能修改不触发。
- 职责：开发版本选择、逐轮推进、适用软件版本字段的对应和开发改进台账；不负责打包、正式发布或 Git 恢复。
- 必要前置：当前任务的已确认范围、实际完成情况，以及 `VERSION.md` 当前开发版本与相关台账。
- 输出位置：`VERSION.md` 开发提交版本、开发改进台账、确认日期与来源，允许范围内实际控制软件版本的已有字段，以及本轮对话记录。

本模块内路径以项目根目录为基准；引用只作导航，仅在对应动作触发时读取。

所有项目以 `v0.0.1` 为开发基线。每完成一轮功能改进，在基线或上一轮开发版本上推进一次；一轮有多个功能点也只推进一次，与 Git、源码预览或打包是否可用无关。纯文档等非功能改动不因此推进版本。升版不表示功能、预览或人工验收通过。

- 已确认不兼容变更：升主版本，后两位归零。
- 新增向后兼容功能：升次版本，修订号归零。
- 修复、优化等功能改进：升修订号。
- 混合改动取最高级别；改动未完成或级别无法判断时记录原因，不臆造完成。

推进前核对新版本高于当前开发版本，且不与开发改进台账重复。Git 可用时再检查版本提交主题；已知 Git 不可用时记录未检查，继续本地版本和对话记录，不为此反复探测 Git。

项目已有构建版本、程序集版本或界面显示版本时，识别真正控制这些值的源文件、生成来源及生效覆盖，在允许范围内按技术栈有效格式与开发版本保持对应；将字段位置、格式映射和核对依据写入现有变更或验证记录。`VERSION.md` 仍是开发版本事实来源，不要求不同技术字段逐字相同，也不得批量修改依赖版本或所有名称含 `version` 的字段。没有适用字段时如实记录，不强制新增版本字段或界面。

开发版本及适用字段在最终验证、源码预览和本轮审核前同步。已完成的检查若发生在相关版本字段变化前，须重新执行受影响的检查；审核返工也按实际改动复查。同一轮已记录版本后不因返工、版本字段对齐或验证重试再次升版；未完成项与待验证结果照实保留，不能用升版冒充完成。受保护字段、来源或映射无法确定时说明并处理必要确认，不绕过任务边界。

执行者可按本规则更新开发版本、台账及对应确认日期和来源；记录本轮版本、日期、范围、验证及截至提交前的 Git 状态。源码预览失败或 Git 不可用不取消已完成改进的升版，但须标明未验证项和实际 Git 状态，不预写提交成功。

实际提交哈希只在核对提交后写入不纳入 Git 的对话记录，避免提交内容自引用。已记录本轮版本后，提交失败、预览重试或重新打包不重复推进；仅需核对异常或补交时调用 `规则/Git恢复.md`。打包本身不额外升版，打包记录由 `规则/打包验证.md` 管理；正式发布版本由 `规则/正式发布.md` 管理。

# Git 异常核对与恢复补交

- 何时读取：需要核对失败或不一致的提交结果，或用户要求修复已知 Git 故障并进入恢复核对时；故障期间普通开发不读取。
- 职责：保留现场、判断提交实际结果、恢复后核对备份并安全补交。
- 必要前置：当前任务与授权、原提交证据；补交还需相关备份索引、清单与内容对象。实际重试或补交前须满足 `规则/Git提交.md`。
- 输出位置：实际补交或重试结果、分类对话记录和 `对话记录/06-Git提交备份.md`。

本模块内路径以项目根目录为基准；引用只作导航，仅在对应动作触发时读取。

## 提交失败后的结果核对

提交前检查失败、提交失败或提交后核对不一致时，保留工作区、暂存区、版本、验证包及恢复证据，记录阶段、原因和恢复线索。不自动清理、覆盖、重复升版或改写历史；失败当轮不盲目重试。

后续先只读核对原分支、HEAD、提交主题和文件、工作区和暂存区、验证结果及最终暂存树指纹。涉及本次指定验证包的版本提交时，再核对 `VERSION.md`、该包清单与哈希；普通提交恢复不检查旧验证包。

- 提交已存在且内容、证据一致：按已提交事实继续，不重复提交。
- 原提交未创建，原因已排除，且内容、暂存及验证证据仍一致：可沿用原版本及本次已检查产品重试一次，不重复追加事件、不覆盖验证包。
- 最终树指纹形成前失败：按当时已有内容指纹与证据判断，不补造不存在的指纹。
- 无法确认对应关系、版本或提交结果：停止相关提交并请用户决定。

## 已知 Git 不可用与恢复补交

已知 Git 不可用期间，不反复要求修复或自动探测；本地索引与清单主要记录拟提交内容、版本关联、验证和未提交状态。项目目标、任务、版本仍以对应根目录事实文件为准，Git 策略不自动改变。用户要求修复后核实 Git 已恢复，才进入补交；不把“已能运行 Git”直接当成提交前置全部满足。

补交前核对相关索引、每轮清单 SHA-256、引用内容对象的字节数与 SHA-256、修改前基线、各轮增改删与顺序、实际代码及验证证据，并检查当前分支、HEAD、工作区和用户已有暂存。损坏对象、缺项或不明归属不能当作完整恢复证据。

能证明各轮完整内容和顺序时，在不覆盖当前工作区、不改变用户暂存选择的前提下逐轮补交，再提交可明确归属的最新进度。只有合并后的当前状态或历史内容不可靠时，只提交可证实的当前累计状态，注明累计范围与当前版本，不编造历史提交、日期、作者或测试。不能安全区分用户暂存、无关改动，或无法保护现场、证明对应关系时，停止相关提交并说明。

实际提交仍逐项核对正常提交前置；保留已有版本衔接，不因补交重复升版。每项核对成功后，将实际提交哈希和结果追加回备份索引及对应分类记录，不修改既存快照或清单，不重复提交。缺项无法证明逐轮恢复时，如实说明限制，不把累计提交说成完整历史恢复。

# 本次失败打包目录清理

- 何时读取：本次打包或最终核对失败后，保存错误并核对本次目录的清理条件时。
- 职责：先保存失败证据、逐项核实目标和限定清理；不负责日常工作区或历史产物整理。
- 必要前置：`CONSTRAINTS.md` 中本次适用且仍有效的对应长期预先授权、本次版本和尝试、目录创建及验证状态证据。
- 输出位置：两个待清理目录之外的 `对话记录/04-问题、风险与恢复.md`、记录索引与实际清理结果。

本模块内路径以项目根目录为基准；路径模式不是实际路径或命令。引用只作导航，仅在对应动作触发时读取。

1. 先将脱敏错误、失败阶段、版本、工作与最终目录路径及必要恢复线索保存到两个待清理目录之外，并更新索引；日志无法安全保存时停止清理。
2. 关闭或等待本次受管构建进程。分别确认本次新建工作目录 `产物/工作/<开发版本>/<尝试标识>/` 和本次尚未通过最终验证、未交付目录 `产物/验证/<开发版本>-<尝试标识>/` 是否存在并属于本次失败尝试。
3. 对每个目标单独解析实际绝对路径，核实其位于对应根目录内；核对目录归属、内容、不含用户资料，检查链接及重解析点不会越界，并确认相关进程已停止。只清理逐项核实通过且授权精确匹配的目标。
4. 逐项记录实际结果。清理失败则保留余留并报告；路径、归属、内容、进程、日志、验证状态或平台权限不明时停止并说明，不扩大范围。

最终目录已通过最终核对、已交付或状态无法确认时不得清理。其他尝试、已验证产品、发布物、用户资料和必要日志一律不在范围内。项目按 Git 不可用例外完成初始化后，Git 故障本身不取消已生效授权；每次仍须满足全部适用条件及平台限制。本模块不产生额外删除权限。

# 正式发布与发布事实

- 何时读取：用户明确要求正式发布、确认发布模式或变更发布事实时；初始化需核对发布配置时只读适用配置条件。
- 职责：发布模式与版本前置、指定产品证据核对、发布状态和历史；不负责日常升版或验证包管理。
- 必要前置：配置核对只需 `CONSTRAINTS.md` 和 `VERSION.md` 的相关字段；实际发布还须明确发布要求或已确认发布流程、适用目标边界及指定产品证据。
- 输出位置：已授权发布目标，`VERSION.md` 发布模式、正式版本、状态、历史、确认日期和来源及对应对话记录。

本模块内路径以项目根目录为基准；引用只作导航，仅在对应动作触发时读取。

## 配置与版本

`VERSION.md` 是发布动作、完成判定、版本及发布历史的唯一来源。发布模式或正式发布事实仅按用户明确确认或已确认发布流程更新；执行者据实同步对应确认日期和来源，不擅自启用发布。

| 发布模式 | 必须满足的字段与状态 |
| --- | --- |
| 未启用 | 发布动作、完成判定、内部构建号格式和当前正式版本、构建号、日期、状态均为“不适用”；不得形成发布候选或正式发布。本地 EXE 验证包不属于二者 |
| 内部构建 | 定义发布动作、完成判定和内部构建号格式；首次构建前构建号与日期为“未产生”，形成后记录实际值；正式版本和状态为“不适用” |
| 正式发布 | 定义发布动作、完成判定、当前正式版本和状态，发布目标边界不得为“不适用”；需关联构建号时定义格式并记录实际值，否则格式及构建号为“不适用”；草稿、候选日期为“未产生”，已发布日期为实际日期 |

模式、正式版本或状态实质变化时同步全部相关字段，清空或按现模式填写旧值，不沿用前一模式或前一版本事实。

正式版本规则：不兼容变更、发布流程变化、对外接口或发布物结构变化升主版本；向后兼容功能新增升次版本；面向用户的修复、文档或构建修正升修订号。预发布格式为 `vX.Y.Z-alpha.N`、`vX.Y.Z-beta.N`、`vX.Y.Z-rc.N`，正式版为 `vX.Y.Z`。普通 Git 提交不自动递增正式版本。

## 指定产品与发布

用户决定正式发布时，先询问并确认使用哪个版本；同版本存在多个验证包且未指定具体产品时询问选择。核对已确认动作、目标、运行要求、主程序与必要依赖清单、逐文件哈希和验证证据。

选择旧版本时先核对该版本已有产品和证据；不足时停止相关发布并说明，不擅自切换源码、重新构建或把当前版本冒充旧版本。日常不管理旧包，不妨碍本次已授权的指定产品核对。

`git push`、改写历史、清理工作区、发布、替换正式产物和外部写入须当次明确授权，或符合 `CONSTRAINTS.md` 中仍有效且精确匹配的长期预先授权；本地打包授权不等于发布授权，也不代替平台限制。

## 状态与历史

- 草稿：已确定正式版本，尚未形成待核对的候选证据。
- 候选：已形成可验证候选，尚未完成全部证据核对，不得说已发布。
- 已发布：发布动作实际完成、证据核对通过，且发布历史已有与当前正式版本一致的记录后才可填写。

“已发布”时须始终存在上述历史记录。当前正式版本改为尚无相符记录的版本时，状态同步改为草稿或候选。历史只记录有证据的正式交付；确需如实记录已发生但证据缺失的交付时明确写“发布证据缺失”，不能据此标为已发布。无 SHA-256 的交付在历史填“不适用”及原因；不得依据目录名、文件时间或记忆补写哈希与测试。日期按 `AGENTS.md` 约定记录。

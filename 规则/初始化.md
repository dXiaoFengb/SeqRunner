# 项目初始化

- 何时读取：首次配置项目，或配置变化需要重新核实初始化条件时；普通已初始化任务不重复加载。
- 职责：配置依赖、初始化状态及已知 Git 不可用例外；不判定立项结束，不授权功能实现、打包或发布。
- 必要前置：`CONSTRAINTS.md` 的实际配置、`VERSION.md` 的版本字段、`README.md` 的项目档案及其确认来源；需要执行 Git 初始化或忽略核验时才读 `规则/Git提交.md`。
- 输出位置：上述文件的已确认配置和 CONSTRAINTS 状态、日期、来源，及适用的本地记录。本文路径均以项目根目录为基准；引用按当前动作触发，不递归读取全部模块。

## 配置与判定

新项目状态为“待初始化”，不表示项目不存在，也不阻止立项访谈。以下条件完成后，执行者可据实改为“已初始化”，不得自行决定尚未确认的长期策略：

1. CONSTRAINTS 的适用配置均为有效已决定值并满足字段依赖。Windows EXE 的验证包策略与三个根目录按该文件配置；具体打包方式可在用户要求时再核实。使用 Git 时按已确认技术栈准备并核验 `.gitignore`，技术栈未知时不预置通用忽略文件；现有仓库先核对，不把初始化当作覆盖索引的授权。
2. VERSION 的当前发布模式及依赖字段有效；所有项目均保留开发版本。发布模式的依赖条件按 `规则/正式发布.md` 核对，仅在配置相关字段时读取，不执行发布动作。
3. README 的技术栈、目录结构、构建命令、测试命令已明确，不适用的填“不适用”。核心文件和预置记录骨架保留；普通不适用项填“无 / 不适用”，记录区、交叉引用区和索引最新条目在无事实时保持空白，不以占位符充当配置。

项目名称不是前置条件。未确定的产品或任务问题集中到 TASK 待决问题；不扫描全仓库 TODO 作为初始化条件。立项是否完成只按立项规则，已初始化不代表需求收敛或允许实现。

## 已确认 Git 不可用的例外

Git 不可用且其他条件完成时可标为“已初始化”，记录故障原因与所用例外；`.gitignore` 保持实际状态，无法核验时为“待确认”，暂不提交，不伪填已核验或提交成功，不改成“不使用 Git”。由 `对话记录/06-Git提交备份.md` 和本地内容清单主要记录拟提交范围、版本关联、验证及未提交状态；项目目标、任务、版本仍以对应根文件为准。

本地备份在实际改动前按现有备份规则开始，记录不依赖 Git。不反复探测或催修已知故障；用户要求修复并核实恢复后，再进入 `规则/Git恢复.md`。该例外不取消 CONSTRAINTS 中已经生效的失败打包清理授权，每次清理仍须满足其全部条件。

## 日期与来源

初始化状态更新时同时填写 CONSTRAINTS 的最后确认日期与来源；适用长期取值实质变化时也更新。来源写清“来源类型：用户当场确认 / 已确认需求 / 其他可追溯来源；定位：对话摘要、需求路径或主记录 ID；核验：完成的字段、文件及适用例外”，不只写“用户同意”。日期用实际日期，无法取得时保持“待填写”，不预估回填；字段未变化且只改拼写、格式或失效引用时不更新。

文件级日期表示最近一次长期取值实质变化，各授权行日期只属于该项授权；日期与来源是变更留痕，不是初始化必填配置。`.gitignore` 从已核验退回待确认属于收紧，不因此更新长期确认日期与来源。其他规则或长期策略的实质修改须具备授权并按 `规则/治理修改.md` 处理。
